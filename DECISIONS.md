# DECISIONS.md — Non-obvious choices and reasoning

## LLM

**DeepSeek via OpenAI SDK, not a custom client.**
The spec calls for `openai` package with `base_url="https://api.deepseek.com"`. This is exactly what's implemented. No DeepSeek-specific packages exist that would be worth using.

**Temperature split: 1.3 for scripts, 1.0 for ideation, 0.0 for metadata.**
DeepSeek's own docs recommend high temperatures for creative writing and zero for extraction tasks. This matches what we need: wild, energetic scripts vs. deterministic JSON metadata parsing.

**`response_format={"type": "json_object"}` everywhere structured output is needed.**
Eliminates JSON parse errors in 99%+ of calls. Only add this where JSON is the expected output — not for free-form moderation checks.

## TTS

**Per-segment synthesis, not full-script synthesis.**
Sending the entire 2,500-word script as one API call risks timeouts and makes alignment harder. Sending per-segment (per countdown item) gives clean audio chunks that directly map to images. Segments are concatenated with 0.8s silence between items, generated by FFmpeg `aevalsrc=0` filter.

**Fish Audio as primary; ElevenLabs as fallback.**
Fish Audio is ~$15/1M characters vs ElevenLabs at ~$22/1M (Starter). Both use simple REST APIs. The adapter pattern means swapping is one env-var change.

**Voice ID locked in `config/voice_config.json`, exposed via `TTS_VOICE_ID`.**
Channel consistency requires the exact same voice forever. The config file is version-controlled; the actual voice ID is set once during `chill-agent init`.

---

## Images

**Replicate Flux 1.1 Pro for image generation.**
Black Forest Labs' Flux 1.1 Pro produces the best flat-cartoon quality for the style we're locking in. SDXL local fallback is available for offline/cost-zero testing.

**Thread pool (max 4 workers) for parallel image generation.**
asyncio would add complexity for what is ultimately a blocking HTTP call. `concurrent.futures.ThreadPoolExecutor(max_workers=4)` is simpler and fast enough. Cap at 4 to avoid Replicate rate limits.

**Style suffix locked in `config/style_suffix.txt` and appended to every prompt.**
The suffix "flat cartoon illustration, bold black outlines, limited vibrant color palette..." is appended to every image prompt. This is the single source of truth for visual consistency. Never bake it into code.

---

## Video Assembly

**FFmpeg `zoompan` filter for Ken Burns.**
`zoompan` is the native FFmpeg approach and avoids external dependencies. Direction alternates per segment (zoom-in, zoom-out, pan-left, pan-right) for visual variety.

**Sidechain compression for music ducking, not just volume mixing.**
Simple `amix` at 12% music volume is the baseline. When `ENABLE_SIDECHAIN=true`, `sidechaincompress` is used to dynamically duck music under voice. Default: sidechain OFF for simplicity; a fixed 12% mix is clean enough and avoids ffmpeg filter complexity that can break in edge cases.

**Per-segment MP4 → concat → mux approach, not one giant filter_complex.**
Easier to debug, enables resumability (if segment 4 crashes, segments 0–3 are already encoded), and avoids the memory usage spike of a 15-minute filter_complex graph. Trade-off: slightly slower due to multiple encode passes. Acceptable for a VPS running overnight.

---

## Alignment

**WhisperX over plain Whisper for word-level timestamps.**
Whisper only gives segment-level timestamps. WhisperX adds forced alignment via phoneme models (wav2vec2), giving word-level precision needed for accurate chapter markers and captions.

**Graceful degradation if WhisperX unavailable.**
If WhisperX is not installed (e.g., no CUDA, no torch), alignment falls back to evenly-distributed timestamps based on word count. Chapter markers will be approximate but the video will still assemble. This is logged as a WARNING.

---

## Database

**SQLAlchemy 2.0 with SQLite.**
Zero-ops, file-based, and perfect for a single-process pipeline. SQLAlchemy's ORM gives clean model definitions and makes future migration to Postgres trivial if needed.

**Alembic for migrations.**
Even for SQLite, schema migrations are version-controlled. Running `alembic upgrade head` is part of `chill-agent init`.

---

## Scheduling

**APScheduler in-process as primary, with system cron fallback.**
APScheduler can be started with `chill-agent run` without any OS-level configuration. For production VPS, system cron (`0 */6 * * * chill-agent run-once`) is more reliable (survives process crashes). Both are supported.

**Upload scheduling: next available slot in 6-hour windows (08:00, 14:00, 20:00, 02:00 UTC).**
These windows cover major time zones: 8 UTC = early morning US, afternoon UK; 14 UTC = US morning; 20 UTC = US evening; 2 UTC = late US / early morning Asia. Windows are configurable via `PUBLISH_HOURS_UTC`.

---

## Safety

**Content moderation before TTS/image generation.**
The cheapest point to abort is before we spend money on TTS and images. A DeepSeek call at temperature=0 checking for gore, slurs, sexual content, or real-person defamation costs ~$0.001 and saves ~$0.15+ in wasted API calls.

**MP4 validation before upload.**
Check duration > 3 min, < 20 min; audio track present; no silent segments > 3s. Uses `ffprobe` (ships with FFmpeg). Rejects silently bad videos before burning 1,600 YouTube quota units.

---

## Thumbnail

**Pillow for text overlay, not FFmpeg `drawtext`.**
Pillow is far easier to position text precisely, handle multi-line wrapping, and add stroke/shadow effects. FFmpeg `drawtext` is powerful but brittle for dynamic text.

**2 thumbnail variants (A/B).**
Variant A: text on bottom-left. Variant B: text on top-right. YouTube's built-in A/B thumbnail testing can pick the winner. Both are uploaded; thumbnail_a.jpg is set as the default.

**Font: Anton (downloaded at init).**
Anton is a free Google Font, bold, condensed, and perfectly readable at thumbnail scale. Stored in `assets/fonts/Anton-Regular.ttf`. If not present, Pillow falls back to its built-in font with a warning.

## What I chose NOT to do (and why)

- **No SSML for TTS pauses.** Fish Audio's SSML support is inconsistent. Instead, silence is inserted via FFmpeg between per-segment audio files. More reliable.
- **No sidechain compression by default.** It complicates the FFmpeg filter graph significantly. A fixed 12% music mix sounds fine and is far more debuggable.
- **No Reddit seeding by default.** Implemented behind `--seed-from-reddit` flag. It's a nice-to-have and the ideation stage works fine without it.
- **No web dashboard.** The spec calls it a nice-to-have. `chill-agent stats` in the CLI covers the 80% case. A FastAPI dashboard can be bolted on later.
